# Runbook 07: monitoring and alerts

The design is in [ADR 0005](../adr/0005-monitoring-placement.md). Roles involved: `node_exporter`,
`blackbox_exporter`, `monitoring`, `watcher`.

## What alerts you

| Alert | Fires when | Channel |
|---|---|---|
| HostDown | a server's node_exporter is unreachable over wg-mgmt for 2 min (server or tunnel down) | Telegram |
| ServiceDown | for 1 min, one of these is not active: x-ui, AdGuardHome, nginx, zapret, wg-mgmt, the monitoring services, or the backup/watcher timers | Telegram |
| ProbeFailed | a public port or the DoH lookup fails for 2 min (checked from the other server) | Telegram |
| DiskAlmostFull / MemoryHigh | over 85 % / 90 % for 10 min | Telegram |
| CertExpiringSoon | the domain certificate (DoH, decoy site) expires in under 14 days | Telegram |
| ShortCertExpiringSoon | Server 1's 6-day IP certificate has under 1.5 days left (renewal failing) | Telegram |
| (watcher) | Server 2's Prometheus/Alertmanager is gone for 3 checks in a row | ntfy push |

Telegram messages show [prod] or [staging]. Resolved ones start with "Resolved:".

## Look at it

- **All panels in one place:** the desktop shortcut **Homelab** opens `backups/recovery/panels.html`
  (generated by `ansible-playbook access.yml`), with a button for every panel.
- **Prometheus:** `http://10.99.0.12:9090/classic/alerts` over the homelab-mgmt tunnel (also
  `/classic/targets`, `/classic/graph`). Ubuntu's package has no new web UI, so `/alerts` gives 404.
- **The watcher on Server 1:** `journalctl -u homelab-watcher -n 5`.
- **Grafana at home:** `http://127.0.0.1:3000`, user `admin`. The password is in the vault, with a copy in the git-ignored `backups/phase6/grafana-admin.txt`. Open **Homelab → Homelab overview**.

## Traffic per user (ADR 0009)

- `homelab-xui-exporter` on both servers: `curl http://10.99.0.11:9117/metrics` (Server 1),
  `.12` (Server 2). Reads x-ui.db read-only; only the server's own inbounds.
- Grafana, row "Traffic": per user now, 24 h and 7 days, per server, the relay hop (client
  `rurelay` on Server 2), VLESS clients' last seen.
- Alert `TrafficExporterDown` if it stops or cannot read the database.

## Grafana (home PC, WSL)

- Role `grafana` on `vm-ctl` (the WSL Ubuntu):
  `wsl -u root ... ansible-playbook site.yml -l vm-ctl --tags grafana`.
- It listens on 127.0.0.1:3000 only. Windows reaches it through WSL's localhost forwarding.
- The data source is Server 2's Prometheus over wg-mgmt, so the history has no gaps when the PC was
  off.
- The dashboard is code: `ansible/roles/grafana/files/dashboards/homelab-overview.json`. It is
  provisioned read-only. To change it:
  1. edit the dashboard in the UI and save it as a copy;
  2. export the JSON and replace the file;
  3. re-run the role.
- **Started on demand, not with Windows.** WSL shuts down shortly after nothing uses it, and Grafana
  stops with it. The desktop shortcut **Homelab** (`scripts\Install-HomelabShortcut.ps1` creates it)
  runs `scripts\Open-Homelab.ps1`, which:
  - wakes WSL; Grafana is up about 7 s after a cold start;
  - keeps WSL awake for 8 hours with a hidden `homelab-keepalive` process (`-Hours N` to change);
  - opens the panels page.

  A second click reuses the running keep-alive. `Open-Homelab.ps1 -Stop` ends it early; WSL then
  sleeps within about 30 s.
- **Cost while awake:** the WSL VM takes about 1 GB of RAM (Grafana about 350 MB of it plus
  ~150 MB of bundled plugins); CPU is near zero when idle. Asleep: nothing.
- Use `127.0.0.1`, not `localhost`, from Windows scripts: `localhost` tries IPv6 first, WSL forwards
  only IPv4, and PowerShell then waits for a timeout. Browsers fall back quickly.

## Add a probe

1. Add an entry to `monitoring_probes` in `host_vars/s2-lt.yml`:
   `{name, prober: s1-msk|s2-lt, module: tcp_connect|doh|https_reachable, target, cert: normal|shortlived}`.
   Addresses come from the vault.
2. Apply it: `ansible-playbook site.yml -l s2-lt --tags monitoring`.

## Test delivery

**Staging** has Telegram switched off. To test delivery anyway:

```bash
ansible-playbook site.yml -l vm-staging --tags monitoring -e "alertmanager_telegram_bot_token={{ vault_telegram_bot_token }}"
ssh ops@192.168.0.70 sudo systemctl stop x-ui      # a message in ~1.5-2 min
ssh ops@192.168.0.70 sudo systemctl start x-ui     # "Resolved"
ansible-playbook site.yml -l vm-staging --tags monitoring   # Telegram off again
```

**Watcher:**

1. On staging, set `watcher_enabled: true` with a target.
2. Stop staging's Prometheus. A push should arrive in about 3–4 min.
3. Afterwards, turn it off again: `systemctl disable --now homelab-watcher.timer`.

## Known quirks

- **Package default config at install:** installing Prometheus first runs the package's own config,
  which scrapes `localhost:9100`. On 2026-11-22 that produced one false HostDown. HostDown now
  ignores targets without a `host` label.
- **`force_handlers = True`:** Ansible runs with it, so a failed run still applies the restarts it
  had already triggered. Staging once ran on stale configs because those restarts were lost.
